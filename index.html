Method

How it decides

  1. 1. Learn normal

    Each sensor is modelled from load and ambient temperature using healthy data only, so a busy shift is not mistaken for a fault.

  2. 2. Measure the gap

    The difference between reading and expectation is scaled to standard deviations. The scale widens automatically if a sensor gets noisier.

  3. 3. Filter and persist

    A median filter removes spikes, a smoothing filter tracks drift, and missing samples are skipped. An alert needs several consecutive exceedances.

  4. 4. Rank and explain

    Severity comes from how far the worst sensor sits from expected. The pattern across sensors is matched to learned fault signatures.

One row per sample, a header row, any number of numeric sensor columns. Optional columns named load and ambient are used as operating conditions, and a column named time or timestamp sets the time axis. The first part of the file is treated as healthy and used to learn normal behaviour.

Limits of this prototype

  • The telemetry is simulated. Results show the method works on these fault models and conditions. They are not a claim about performance on a real plant.
  • The simulator and the detector were written by the same person, so the model family fits the data well. Real machines have nonlinear and drifting behaviour that will cost accuracy.
  • The load change stays inside what a linear-plus-quadratic model can extrapolate. A truly new operating regime needs fresh healthy data.
  • Fault signatures come from four fault types. Anything else is reported as unclassified, with the measured evidence.
